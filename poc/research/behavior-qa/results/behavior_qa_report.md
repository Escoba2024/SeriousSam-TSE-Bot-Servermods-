## Lateral-movement A/B (integration default `strafe_scale=0` vs `1`)

**Integration fact (BotDriver.cpp):** the policy's strafe is written to the action only when `bot_fStrafeScale>0`; the shipped default is 0, so the Human-KI's in-band lateral movement is computed but silently dropped.

**What this offline harness CAN show:** the accuracy cost of enabling it. The aim controller tracks the target from the bot's *current* pose, so self-induced lateral motion adds angular rate the controller lags behind (no self-motion feed-forward), lowering the bot's own hit rate.

**What it CANNOT show:** the evasion *benefit*. Scripted return fire (assumption A9) is range-falloff dps, not dodgeable aimed projectiles, so `survival_s` here does NOT reward strafing. Quantifying evasion benefit requires retail telemetry or an aimed-fire model - explicitly out of scope.
